## 已阅读的实现

这份原型也是 Electron：`main.js` 使用一个覆盖主显示器的透明窗口，`preload.js` 提供鼠标穿透/面板桥接，主要界面和物理引擎位于原生 JavaScript + Canvas 的 `app/index.html`。当前项目是 Electron + React，并为每颗气泡创建独立原生窗口。可以复用物理算法与视觉参数，但需要适配绘制、命中和状态层。

5. Blow it 使用截图中的横向描边按钮；底部直接放 Shuffle 和全局排列工具，不藏进 Floating 的折叠内容。
6. 延续可移动字标和位置记忆，卡片从字标下方展开；取用原型按字母轮廓形成的贴纸视觉，避免再次变成长白条。

## 目标二：移植实际 Squish 模型

原型不是整颗气泡缩放。每颗气泡有 40 个轮廓点，各点保存位移、速度、目标和约束，包含：

- 相邻轮廓点耦合的弹簧与阻尼，3 次子步积分。
- 拖拽的中心惯性，以及中心加速度传到膜边缘的变形。
- 鼠标速度引起的局部 jello。
- 邻泡共享分界线、允许约 9px 的软挤压余量，以及面板墙的射线接触约束。
- 二次曲线平滑轮廓；内圈跟随同一膜形变，文字保持可读。
- 小幅漂浮、成长接触和松手回弹；减少动态效果时降幅。

下一轮应提取这套求解器为独立 TypeScript 模块，使用现有任务、分组、增长和 Focus 状态驱动。先验证当前多窗口层承载连续轮廓和跨泡接触的效果；若窗口同步/裁切成为瓶颈，再替换气泡显示层。任务与历史继续由现有主进程保存。

视觉同时参考原型的浅纸色底、分组内环、双层描边，以及随成长增强的遮挡感。绘制、命中和 95% 面积计算需要跟随新的变形轮廓，不能只更换画法而保留旧圆形命中。

## 目标三：分组排列与全局排列是两套明确控制

必须覆盖：

- Work 靠左，School 靠右，互不改变。
- 一个组回到自由位置时，其他组仍保留各自侧边。
- 全部泡泡靠左 / 靠右，包含未分组泡泡，也包含原先设置为其他侧边的组。
- 新任务加入有侧边设置的组时，进入该组队列；全局模式生效时，新任务遵循全局位置。
- 同一条边不足容纳时排到内侧第二列；成员增长和 Pop 后重新收拢空隙。沿边拖动可调整队列顺序。

**原型的实际行为有一个差异：** `lineUp` 只处理“目标边已固定的成员 + 自由泡泡”，其他边固定组保持原位；它主要改 home 坐标，没有持久化一个真正的“所有泡泡靠某侧”模式。因此不能直接照搬这段逻辑来满足“全部靠左 / 右”。

建议的状态规则（待用户确认）：保留“按组排列”和“全局靠左/右”等模式。全局模式覆盖所有组的显示位置，同时保留组自身设置；切回“按组排列”后恢复。全局按钮的选中态与文案应明确其作用范围。

## 沿用已确认的产品规则

现有手势、本地 billboard、可移动 Dock、任务和历史继续保留：单击打开 URL / billboard，双击编辑，右键 Pop；95% 可见联合覆盖率停长；环形配色保留原生图片拖拽与无效颜色格式的修复。

原型里的单击 Pop、右键编辑、Pause Growing、Step、计时条，以及 90% / 80% 停长逻辑，与用户已经确认的范围不同，不随本轮样式和物理迁移加入。示例任务、随机完成历史和原型 localStorage 也不替换当前真实数据。

## 推荐实施顺序与验收

1. 完成新增面板和行内分组管理，确认选组、增删改和 URL 草稿不丢失。
2. 实现分组/全局两级位置模型和边缘队列，验证左右分组、全局覆盖、新任务加入、溢出换列和重启恢复。
3. 移植物理求解、曲线绘制、接触约束与回弹；接入真实轮廓命中和 95% 覆盖率。
4. 回归普通/双击/右键、billboard、可移动字标、配色、增长和历史，制作新的可安装预览与手感复核场景。

验收场景至少包括两组分居左右、全部泡泡切到同一边、两泡挤压、与展开面板接触、队列内增长/Pop、1/10/30 泡，以及透明区域点击穿透。完成静态检查或网页预览不代表原生桌面穿透和动态性能已通过。
